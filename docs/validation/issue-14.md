## Ejecución reproducible

Entorno: Windows con Bash/WSL para el runner PostgreSQL; Node `v24.14.1`, pnpm `11.25.0`, Next.js `16.4.2`, Biome `2.2.0` y PostgreSQL `16.15`. `scripts/test-db.sh` crea y elimina un clúster local desechable, no consume `DATABASE_URL` ni `PGHOST`. Usa claims y UUID sintéticos; el dueño de fixtures es `40000000-0000-4000-8000-000000000002`, el administrador sin membresía `40000000-0000-4000-8000-000000000001`; las carreras usan dos sesiones locales. No se usaron OAuth, cuentas/datos reales, `.env`, servicios externos, bypass, CUA/IAB, navegador, runner nuevo ni producción.

- RED inicial DB antes de `027_task_recovery.sql`: `pnpm test:db` exit 3, `function public.delete_task_p(unknown, text, uuid, unknown) does not exist`. Después de implementar RPC/migración y actualizar el call site versionado, la suite completa pasó.
- `pnpm test:db`: exit 0; aplica migraciones 001–027 y termina `Database regression tests passed (disposable PostgreSQL).` Incluye autorización, replay/conflicto, límite de siete días, padre eliminado, destino, purge y ambas carreras concurrentes restore-vs-purge. La eliminación con reloj controlado bajo Denver informa `2005-04-09 13:00:00-06` y 604800 segundos desde `2005-04-02 12:00:00-07`.
- La lista de recuperación prueba que `can_restore` coincide con `eligibility_checked_at < expires_at`; el timestamp se evalúa una vez por consulta mediante CTE materializado con `clock_timestamp()`, incluso cuando el RPC se invoca dentro de un bloque `DO`.
- `pnpm test:unit`: exit 0, 65/65; incluye regresiones de deadline anclado tras respuesta, estado obsoleto durante refresh/fallo, action gate e IDs asociados para destino.
- RED/GREEN de deadline UI: el test focal falló primero con export ausente para `isTaskRecoveryRestorableAtMonotonicTime`; luego pasó con latencia simulada (request monotónico 1000, respuesta 5000): sigue disponible a 59.999 ms desde respuesta y se oculta a 60.000 ms. Este test valida el helper relativo al anchor, no acredita el instante visual real entre DB y recepción.
- RED/GREEN de refresh tras suspensión: tras tener el helper de deadline disponible, el test focal mostró `ready` en vez de `loading` al reanudar con una fila obsoleta, y `ready` en vez de `error` cuando fallaba ese refresh (9 pass/2 fail). - RED/GREEN del action gate: el test de elegibilidad obsoleta falló con actual `true`/esperado `false` mientras un refresh estaba pendiente (11 pass/1 fail); ahora el helper y la ref síncrona bloquean restore hasta respuesta DB actual.
- RED/GREEN de IDs: el test de IDs falló inicialmente por export ausente; tras añadir IDs distintos con `htmlFor` al select asociado pasó.
- RED/GREEN de reloj de lista: la primera DB corrida encontró que `statement_timestamp()` heredaba el inicio de un bloque `DO` y era anterior a `deleted_at`. La solución usa un CTE materializado con `clock_timestamp()` por consulta; `pnpm test:db` final pasó y verificó el timestamp junto con `can_restore`.
- RED/GREEN de errores y privacidad: las pruebas focales fallaron primero con export ausente (`taskRecoveryLoadErrorMessage`, luego `shouldClearTaskRecoveryItems`); tras extraer los mapeos puros, la suite focal pasó 8/8. El acceso denegado limpia el contenido previamente cargado, mientras un fallo incierto conserva entradas autorizadas conocidas.
